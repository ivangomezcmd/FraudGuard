FraudGuard
Video Demo: https://youtu.be/qUo9v6NXri0
Description:

FraudGuard es una aplicación web construida con Flask, SQLite y Python que ayuda a pequeñas empresas y autónomos a detectar facturas fraudulentas antes de pagarlas. La idea del proyecto nace de un problema real y cada vez más común: el llamado "fraude del proveedor" o "fraude del CEO", en el que un estafador suplanta a un proveedor legítimo y envía una factura con un número de cuenta bancaria alterado, consiguiendo que la empresa pague sin darse cuenta a una cuenta fraudulenta. FraudGuard resuelve este problema permitiendo al usuario mantener un registro de sus proveedores de confianza, junto con su número de cuenta oficial, y comparar automáticamente cada factura recibida contra ese registro para detectar discrepancias.

La aplicación cuenta con un sistema completo de autenticación de usuarios: registro, inicio de sesión y cierre de sesión, con las contraseñas almacenadas siempre cifradas mediante "generate_password_hash" de Werkzeug, nunca en texto plano. Las sesiones se gestionan con Flask-Session, guardadas en el sistema de archivos en lugar de en cookies firmadas, siguiendo el mismo patrón que se enseña en el proyecto Finance de CS50. Todas las rutas internas de la aplicación están protegidas mediante el decorador "login_required", definido en "helpers.py", que redirige a "/login" a cualquier usuario que intente acceder sin haber iniciado sesión.

Una vez dentro, el usuario dispone de tres secciones principales, accesibles desde el menú de navegación superior:

Dashboard, la página principal ("/"), muestra un panel de control con el historial completo de facturas que el usuario ha analizado, ordenadas de la más reciente a la más antigua. Cada fila incluye el número de factura, el proveedor, el importe, el número de cuenta utilizado y, sobre todo, el estado del análisis, resaltado con un color distintivo: verde para "Aprobada (Segura)" y rojo para "Fraudulenta (Cuenta alterada)", lo que permite identificar de un vistazo cualquier factura sospechosa.

Proveedores ("/suppliers") permite al usuario construir su propia lista de proveedores de confianza, guardando el nombre de cada empresa junto a su número de cuenta o IBAN oficial. Esta ruta incluye validaciones tanto en el formulario como en el servidor: el número de cuenta debe tener entre 8 y 34 caracteres y solo puede contener letras y números, rechazando símbolos extraños mediante una expresión regular ("re.search(r"[^a-zA-Z0-9]", account_number)"). Desde esta misma página el usuario puede eliminar proveedores que ya no necesite mediante la ruta "/delete_supplier", protegida para que un usuario únicamente pueda borrar sus propios proveedores.

Analizar Factura ("/check") es el corazón funcional de la aplicación. El usuario introduce los datos de una factura recibida: nombre del proveedor, número de factura, importe y número de cuenta indicado en esa factura. La aplicación busca entonces si ese proveedor existe entre los proveedores de confianza del usuario. Si no existe ningún registro con ese nombre exacto, la factura se marca como "Sospechosa (No registrado)"; si el proveedor existe pero el número de cuenta no coincide con el guardado, se marca como "Fraudulenta (Cuenta alterada)"; y si todo coincide, se marca como "Aprobada (Segura)". El resultado de cada análisis se guarda en la tabla "invoices" de la base de datos, vinculado al usuario que lo realizó, para poder consultarlo posteriormente desde el Dashboard.

En cuanto a los archivos del proyecto: "app.py" contiene toda la lógica de las rutas de Flask descritas anteriormente. "helpers.py" incluye dos funciones de apoyo reutilizadas del material de CS50: "apology()", que genera una página de error estilizada tipo "meme" cuando algo falla (por ejemplo, campos vacíos o contraseñas que no coinciden), y "login_required()", el decorador que protege las rutas privadas. "schema.sql" define la estructura de la base de datos, con tres tablas: "users" (usuarios registrados), "suppliers" (proveedores de confianza, vinculados a cada usuario) e "invoices" (historial de facturas analizadas). La carpeta "templates/" contiene todas las vistas HTML: "layout.html" como plantilla base con la barra de navegación común, "login.html" y "register.html" para la autenticación, "index.html" para el dashboard, "suppliers.html" para la gestión de proveedores, "check.html" para el formulario de análisis, "add_invoice.html" como formulario auxiliar, y "apology.html" para los mensajes de error.

Durante el desarrollo se tomaron algunas decisiones de diseño relevantes. Se optó por distinguir tres estados de resultado (Aprobada, Sospechosa y Fraudulenta) en lugar de un simple sí/no, ya que un proveedor no registrado no es necesariamente fraudulento —puede ser simplemente nuevo— mientras que una cuenta que no coincide con un proveedor ya conocido sí representa una señal de alarma mucho más grave. También se decidió validar el número de cuenta tanto en el formulario como en el servidor, ya que confiar únicamente en la validación del navegador dejaría la aplicación vulnerable a peticiones manipuladas directamente contra el servidor.

Para el desarrollo de este proyecto se ha utilizado como asistencia la herramienta Claude (Claude Code), empleada para depurar errores de configuración del entorno, resolver problemas de importación de librerías en el Codespace y revisar la lógica del código.
